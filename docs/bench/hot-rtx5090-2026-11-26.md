## 测量范围

每个样本启动一个新的 Windows x64 测试进程。所有场景使用 VIctory 的 host 后端。除两个明确标注的 GPU timestamp 指标外，时间都是 Windows 进程内的墙钟时间。Windows 进程启动、Cargo、生成输入、查询整卡状态和额外的读回断言在对应计时区间之外。单个 PSO 的像素回读沿用原计算场景，计时截止于 PSO 可用。

| 热点 | 负载和测量边界 | 每轮的通过条件 |
|---|---|---|
| 3，刷新与标记页回写 | 4,096 个 64 KiB 页，256 MiB。单测 `Shadow::update`。另测一次 `Host::execute`，覆盖 `copy_back_marks`、`copy_back_marked`、重复范围去重及 withheld 重叠处理。测试预置提交完成时应有的页标记和 host 字节。1,024 次普通声明覆盖 512 个八页范围，另有 32 个重叠声明 | 刷新后核对 host 的全部 256 MiB。回写后逐字节验证 240 MiB 新内容、16 MiB 保留原值，并断言实际回写计数 |
| 6，bindless 描述符同步 | 32,768 槽的跟踪堆。分散改写 1,300 或 14,400 个槽，使用指向 256 个不同常量的记录。只计 `descriptor::sync_heaps`，包含实际 `HostHeap::sync_slots`，记录扫描槽数 | 全堆的记录 ID 和代数与预期一致。另由 GPU 从真正的 D3D12 堆逐个读取每个被改写槽，比较返回的常量 |
| 7，多 mip 纹理上传 | 8 张 2048×2048 RGBA8 纹理，4 个 mip，4 KiB 平铺。整批初传 32 个子资源、170 MiB。随后每张只改 mip 1 的 32×8 区域，共写 8 KiB，实际重新上传 8 个子资源、32 MiB。分别计整批 `Host::execute`，含 `refresh_all` 并行刷新、局部 detile、复制和 fence | 每次初传和局部更新后，分别把每张纹理的每个 mip 从 GPU 读回，按行比较全部有效像素，包括各 mip 独有的非对称位置标记和未更新区域 |

## 重跑与对比

从独立副本根目录在 WSL2 运行。脚本默认使用相邻的 `../toolchain/env.ps1` 和副本自己的 `target`。其他目录可通过环境变量 `VICTORY_BENCH_ENV` 指定工具链脚本。输出目录应使用新名字。WSL 包装脚本管理本地构建槽和 GPU 窗口，Windows PowerShell 调用原生测试进程，再由 Rust xtask 计算统计量。装有 Linux Rust 的 WSL 也可使用 `cargo xtask bench-hot build|smoke|run` 和 `cargo xtask bench-compare A B`；Windows 工具链终端可直接运行后一个对比命令。

```bash
# 非正式调通，不暂停桌面服务
bash tools/bench/hot.sh build
bash tools/bench/hot.sh smoke --runs 3 --out /tmp/victory-hot-smoke

# 一键正式采样，先排队构建，再保留本机构建槽，由 gpu-quiet 包住采样和恢复
bash tools/bench/hot.sh run --runs 30 --out docs/bench/logs/hot-next

# 在控制台输出各项中位数变化、区间、是否跨零和两批正确性
bash tools/bench/hot.sh compare docs/bench/logs/hot-rtx5090/results.json docs/bench/logs/hot-next/results.json
```

比较代码版本时，可在同一个 `gpu-quiet` 窗口内按对采样。先为两边各自构建热点二进制，传入包含构建清单的副本或其 `target` 目录。WSL 上的 `cargo xtask bench-hot ab` 接受同样的参数。

```bash
# A/A 检查噪声：两个参数指向同一个已构建的二进制
bash tools/bench/hot.sh ab --a ../ab-new --b ../ab-new/target --runs 15 --out docs/bench/logs/ab-fix-cost/aa
# A/B：每边 30 个新进程，奇数对先 A，偶数对先 B
bash tools/bench/hot.sh ab --a ../ab-old --b ../ab-new --runs 30 --out docs/bench/logs/ab-fix-cost/ab
```

正式单组和 A/B 采样都用单独进程跑 D3D12 计算预热。每约 200 ms 查询一次，连续 3 秒达到 P0/P1、核心至少 2500 MHz、显存至少 13000 MHz、PCIe Gen5 ×16 后退出预热进程，再读一次确认，然后启动待测进程。每侧保存样本前后遥测、预热轨迹及汇总范围。未达标的尝试记入该侧的 `invalid_runs`，在同一个配对位置重试；每侧超过 `floor(N/10)` 次即终止，正确性失败立即终止。

`paired.json` 给出两边中位数，以及每对变化百分比的中位数、按整对重抽 5,000 次的百分位区间。19 个耗时指标还提供 Bonferroni 校正后的家族 95% 区间。A/A 的任一耗时指标逐项 95% 区间排除零或无法估计时，命令保留结果并返回失败；家族检验单独记录。样本前后两次遥测反映边界状态，区间内可能变频。

比较工具对两批独立进程分别有放回抽样 5,000 次，用中位数变化百分比的 95% bootstrap 百分位区间判断是否超出本次观测噪声。区间排除 0 表示超出，两批的环境差异、日间漂移和多重比较仍需结合原始记录解读。JSON 保存每轮指标、采样前的设备状态、工作量、被测提交、可执行文件 SHA-256 和本地源码差异指纹。显存峰值按 10 ms 轮询进程 DXGI local usage 取得，是采样下界，工作集使用 Windows 提供的进程生命周期峰值。

D3D12 Debug Layer 和 GPU-based validation 待安装 Windows 图形工具后补测。此次正确性结论来自应用层断言和真实 GPU 回读。
