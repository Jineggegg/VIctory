### 强制 WARP 的三项失败

两项开关均为 1。以下用例在 B 的并行全测和 A 的定向单线程复测中均在创建固定 32-lane wave 管线时失败。A 的这组定向测试为 8 通过、3 失败。B 的硬件全测通过了这三个用例。[B 全量输出](logs/round1-acceptance-2/correctness/diagnostics-warp.txt) · [A 定向复测](logs/round1-acceptance-2/correctness/A-warp-synthetic.txt)

- `a_mask_joined_with_data_at_a_uniform_loop_is_its_number`
- `permutes_mask_high_address_bits_and_divergent_branches`
- `permutes_read_the_lane_named_and_zero_from_lanes_left_out`

shader 测试先请求硬件，再请求 WARP。`Host::new(false)` 在强制 WARP 环境中也创建设备为 WARP，但上述用例仍按请求参数判断管线失败能否跳过，输出中因而写成了 `hardware: no pipeline for a wave of 32`。A 和 B 的这两个源文件分别逐字相同，上游 `63bcca4` 中也可查到环境覆盖和对应断言。三项失败已在五项优化之前实测出现，本轮没有观察到它们与合并产生交互。WARP 在这三项上仍缺少实际执行结果。[设备选择](../../crates/victory-shader/src/emit/host.rs) · [合成测试](../../crates/victory-shader/src/emit/synthetic_tests.rs)
