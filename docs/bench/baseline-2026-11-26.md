## 测量范围

- **计算写纹理**使用仓库手写的 GFX10 计算程序，从 victory-shader 的 IR、控制流、资源跟踪与 IO 提升进入 DXIL 发射。计时包含合成着色器对象构造。随后通过兼容层管线工作线程取得可用的 D3D12 PSO。PSO 时间包括入队、等待与根签名创建。接下来分配描述符堆、构造放置纹理和 UAV、绑定根常量与表，录制 dispatch，执行并等待提交完成，读回两个 RGBA32F 像素。每次与参考值逐分量比较，第一个为 [1, 0.5, -0.25, 2]，第二个为 [0, 0, 0, 0]。
- **深度绘制**用合成 HLSL 生成顶点着色器，通过兼容层的管线流、命令列表入口、视口、裁剪、深度范围与重置逻辑绘制四个 D32_FLOAT 深度像素。计时包含着色器编译、管线就绪、资源准备、两次提交、同步、回读比较与对象释放。RTX 5090 的参考值为 [0.25, 0.5, 0.25, 0.25]。不同适配器是否支持深度范围由 D3D12 功能查询决定。
- **统计口径**为 CPU 端墙钟时间，单位为微秒。计算场景按连续阶段拆分，二者都不包含 cargo、启动进程或 nvidia-smi 的开销。每个样本启动一个新 Windows 进程，先计算后绘制，系统和驱动缓存可保留。两种场景都用断言检查 GPU 实际返回的值。每个场景读取一次进程工作集和 DXGI 本进程本地显存占用，计算场景在释放临时资源前取样，绘制场景在它返回后取样。这些内存读数为瞬时值。
- **验证和日志**在独立的进程里启用 D3D12 Debug Layer 与完整 GPU-based validation。工作负载期间统计 InfoQueue 回调中 ERROR 和 CORRUPTION 消息，完整文字进入日志。计时进程关闭验证。每次启动场景前记录 NVIDIA UUID、GPU 利用率、整卡已用显存和温度，Rust 端用 D3D12 设备的 LUID 核实实际适配器。p95 和 p99 用最近秩，中位数在偶数样本取中间两项平均，标准差为样本标准差。一次轻量渲染的耗时不能换算为 GTA VI 游戏帧率。

## 一键复现

在 Windows x64 Developer PowerShell 中安装项目钉住的 Rust 工具链，确保 cargo、git、nvidia-smi 可用，用 VICTORY_DXIL 指定支持 SM 6.6 的 x64 验证器。完整验证还需 Windows 可选组件“图形工具”。本机尚缺该组件，已实测 Agility SDK 1.620.2 的便携运行库同样返回 0x887A002D。用户决定稍后由本人安装。此时运行命令加 `-SkipValidation`，原始报告将验证状态记录为跳过。[便携运行库检查](logs/agility-check.txt)

进入本副本后运行以下命令。本机便携工具链先在同一个 PowerShell 中执行 `. ..\toolchain\env.ps1`。

```powershell
.\tools\bench\run.ps1
```

脚本默认测 100 次，结果保存在 `docs\bench\logs\<运行时间>\results.json`，完整子进程输出保存在同目录的 `run.txt`。只做像素和验证层检查可加 `-CheckOnly`；多卡机器可用 `-GpuIndex` 选择 nvidia-smi 的编号。脚本对每个计时样本先检查 GPU 负载，超过上限会等待，持续繁忙便保留部分结果并退出。构建配置为 `--profile diag --features diagnostics --locked`。每次运行记录提交、源代码改动、CPU、内存、GPU、驱动和 rustc 版本。

```powershell
cargo build --locked --workspace
cargo build --release --locked -p victory
cargo test --workspace --locked --no-fail-fast
```


## 正确性与尚待解决的问题

| 实测范围 | 通过 | 断言或 API 失败 | 进程崩溃 | 显式忽略 |
|---|---:|---:|---:|---:|
| 默认工作区 881 项，含逐例续跑 | 865 | 5 | 1 | 10 |
| 全部特性新增的 18 项 | 17 | 0 | 0 | 1 |

新增特性里的 1 项为本分支的显式基准入口，已用脚本单独执行。完整命令、输出和退出码见[诊断特性补充用例](logs/diagnostics-extra.txt)、[像素检查 JSON](logs/pixel-check/results.json)和[像素检查日志](logs/pixel-check/run.txt)。

项目的默认工作区命令在 GPU 库报告两次断言失败，在 shader 库遇到 Windows 异常退出。单线程运行定位到 `emit::memory_tests::heap_direct_texture_reads_mark_their_heap_index`，退出状态为 `0xC0000005`。为避免这个用例遮住后面的结果，按相同 Rust 测试程序的 `--list` 顺序，对其后的每个用例分别启动进程，并保留原始退出码。两次工作区运行和逐例续跑的重复执行只计一次。项目中显式忽略的基准、已知缺陷和需要外部样本的用例按 libtest 的 ignored 单列。含环境守卫、因缺少文件而自行返回的测试沿用 libtest 的判定。

| 用例或模块 | 实际观察 |
|---|---|
| victory-gpu 描述符动态槽 | 测试要求创建的宿主堆至少有 2097152 个槽，RTX 5090 上走了较小堆的回退路径，断言失败。 |
| victory-gpu 内存页表视图 | 提交后读出的数据先通过比较，之后检查两组视图槽均不低于 262144 的断言失败。代码允许在空间不足时改用动态槽。 |
| shader 直接索引纹理的读取标记 | 串行运行该用例时，Windows 报访问冲突，测试进程提前退出。异常原因仍需单独调查。 |
| shader 按元素读取带步长缓冲区 | 硬件回读以 101、104、107 开始，参考值以 200、201、202 开始。 |
| shader 读取空缓冲区视图 | 硬件 dispatch 返回“参数错误”，用例未得到预期的零值。 |
| shader 指定层级的纹理 gather | 硬件第 0 个 lane 回读 [0, 1, 0, 0]，参考为 [0, 0, 0, 0]。 |

两项 GPU 堆断言对应着色器索引空间和宿主堆容量的实际差异。要保证索引、空视图和 GPU 回读正确，需要同时检验运行时和着色器端；本基线保留了原断言和原参考值。默认与全部特性下的 Clippy 都通过。基准统计公式用固定输入在 Windows PowerShell 中验证。[首次完整测试](logs/initial-workspace.txt) · [串行工作区](logs/workspace-serial.txt) · [shader 剩余用例](logs/shader-remainder.txt) · [默认 Clippy](logs/clippy-default.txt) · [全部特性 Clippy](logs/clippy-all-features.txt) · [统计公式验证](logs/statistics-check.txt)
