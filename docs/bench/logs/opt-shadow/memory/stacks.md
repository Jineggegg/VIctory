# 回写进程的线程栈

在普通构建间隙里以六种顺序各跑一遍同一组正式二进制。外部观测程序读取每个原生线程当时已提交的栈地址区间，再用 QueryWorkingSetEx 逐个 4 KiB 页计算实际驻留量。六轮共 54 次记录，所有线程的栈都成功查询。程序输出阶段标记后仍继续执行，因此此表用于分析内存来源；正式峰值取自独占显卡窗口的 30 轮。[逐次采样](stack-samples.json)

| 实现 | 阶段 | 线程数中位数 | 全部线程的常驻栈 KiB | 当时工作集 MiB | 到此为止的峰值 MiB |

| A | 大副本刷新前 | 25 | 472 | 606.59 | 655.89 |

另用 QueryWorkingSet 读取驻留虚拟页，再用 VirtualQueryEx 区分私有、映射和映像页。回写后，三臂的映射页中位数均约 1.41 MiB，映像页约 39.61、39.66、39.67 MiB。进程在查询期间释放大块映射，部分样本包含最多数百 MiB 无法再分类的页。此观测不能将 1.338 MiB 的正式峰值差逐字节精确归因。可直接确认的是额外线程及其驻留栈、每个并发分块的暂存上限，以及三档和长跑的实测结果。[各次驻留页分类](resident-regions.json) · [三档内存](scale.md) · [进程寿命](lifetime.md)
