# 对照方法

本次比较的硬件为 RTX 5090、Core Ultra 9 285K 和 128 GB DDR5。旧报告与修复后的报告处于不同显卡时钟状态，两份报告之间的差值不能用于判定候选收益。开发基线固定在 `6b1e408`。每组正式对照使用同一次 GPU 空闲预留，Windows 原生进程按 AB、BA 交替运行。预热门槛是 P0 或 P1、核心至少 2500 MHz、显存至少 13000 MHz、PCIe Gen5 x16。每轮开始和结束均保留遥测。

初筛沿用原有 `writeback(host, pages)`，依次覆盖 256、4096 和 16384 个 64 KiB 页。原函数先逐页检查刷新后的内容，再由 `Host::execute` 处理重复声明与 withheld 范围，最后逐页比较全部字节。256 MiB 场景要求 240 MiB 页区间呈现完整的新模式，其余 16 MiB 保持原值。模式值与初始值偶尔相同，因此涉及回写的页大小和实际发出存储的字节数是两个不同的量。

社区初筛按每档 15 对设置。入选实现的补采交换两臂，逐阶段列出结果。比较首要看 256 MiB 的回写和刷新各自用了多久，再检查小批量与 1 GiB 上的变化。涉及不同工作量、错误内容或缺少必要回写的读数单独记录。

初筛分两个时段。第一段在 18:46 UTC 完成，包含九个候选的全部三档，每档 15 对。第一段的两种精确写入方式都通过五项定点检查。将每个进程的 256 MiB 回写与刷新耗时相加，再取候选与同对基线耗时之比的中位数，本地掩码写入比基线少用 49.36%，复用社区写入指令的版本少用 48.60%。第二段开头以同一份基线、预热程序和本地候选二进制再测 5 对。这 5 对用于检查两个时段的漂移，单独保存。各候选始终与自己同组交替运行的基线比较。[第一段各组](screen-first-half.json)

复核中，回写的配对耗时比由 0.4924 变为 0.4843，相对变化为 −1.65%（逐项 95% 区间 −4.82% 至 +4.95%）。刷新的比值由 0.5354 变为 0.5673，相对变化为 +5.95%（+1.91% 至 +8.35%）。同一实现两段都能缩短刷新时间，但缩短的幅度有变化。各阶段分别在本阶段内重抽整对样本，再计算两个阶段比值的相对变化。复核只有五对，跨段的小差距留给同窗口直接测量判定。[两段复核](continuity.json)

原版 gradient 和完整 19 项套件用于检查其他路径及内存。逐项变化采用每对样本耗时比值的中位数，以固定种子 5090 将整对样本重抽 5000 次。原始配对报告同时给出逐项 95% 区间，以及对声明的耗时项数作 Bonferroni 校正的区间。p95、p99 取最近秩，30 次的 p99 等于最大值。尾分位的变化用两臂相应分位数之比估计，区间同样按整对重抽。进程峰值工作集和定时采样的本地显存峰值分别列出。

并发检查包含定点真实 CPU 写入、两个虚拟地址映射同一物理页、一个 CPU 写指令跨页、部分重叠及位图末字。额外的一组真实提交让两个列表在同一页内分别声明有效和 withheld 写入。稀疏刷新另测 256 MiB 两端各 1 MiB 的视图，之后单独请求中间一页，核对下一次请求的内容和实际复制量。Windows 的 D3D12 Debug Layer 仍待安装。

## 终选设计

终选的 A 为未加回写优化的 `177ee68`。B1 使用本地逐字节掩码和 Windows 常驻线程池，B2 使用社区精确存储实现和接入直接大范围刷新的 #2051 常驻池。两个候选共同包含同页有效范围处理、物理别名顺序修复和 #2428 稀疏刷新。三臂都包含相同的着色器生成代码。原版场景先测刷新再测回写，回写中的八页分块至多 512 KiB，低于两个刷新池的大块并行门槛。[三份二进制](final-arms.json) · [正确性检查](tests/integrated-candidates.json)

三档各在独立窗口采样。每轮基线和两个候选各启动一次新进程，六轮依次采用 A/B1/B2、B1/B2/A、B2/A/B1、B2/B1/A、B1/A/B2、A/B2/B1 的顺序。30 轮中每臂在每个位置各运行十次。三组比较按同一轮的样本配对，分别计算 B1 对 A、B2 对 A 和 B1 对 B2。小档和大档采用相同的仅测量补丁，直接调用原有 writeback(host, pages)，保留页数、提交路径和逐页校验。中档跑未改动的原版 gradient 和 19 项完整场景，并记录两个内存峰值。首段使用同一份带测量入口的 A 二进制做十轮三臂自检，三组配对各自的回写与刷新逐项 95% 区间都须包含零。原工具的独占槽、GPU 空闲控制、预热、样本有效性和统计函数均被复用；调度顺序和配对结果文件由副本 target 下的临时脚本生成。[本次采样入口](fixtures/hot.sh) · [本次 Windows 采样器](fixtures/hot.ps1)

中档的原版 gradient 与完整 19 项套件各运行 30 轮，分别报告。检查两项热点收益时以同一窗口的直接配对为准。检查其他路径时同时列出逐项区间和套件内的多项校正区间，另逐项查看两个内存峰值及 p95、p99。30 轮能发现的变化幅度有限；区间包含零时，报告给出区间，不把它解释为两个实现等效。显存使用 DXGI 的采样值，以十进制 MB 计；进程工作集使用 Windows 记录的峰值，以 MiB 计。

复现三臂终选时，将上述两个采样脚本放入基线副本的 target/shadow-triplets 下，用该目录的 hot.sh 调用 ab，按顺序通过 --a、--b、--c 传入三个已构建的副本。小档和大档的页数、提交和检查见[测量入口](fixtures/scale.md)。[并发检查](fixtures/correctness.md) · [稀疏场景](fixtures/sparse.md)
