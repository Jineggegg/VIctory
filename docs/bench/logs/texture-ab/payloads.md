# 纹理候选的读回与传输量

各臂使用同一份合成像素和同一组跟踪页。独立 Windows 进程中，每次提交后从 RTX 5090 读回每张纹理全部 mip 的每个有效行。以下为四个 smoke 各一次的实测字节，单位 MiB。正式耗时另外采用配对采样。

每格依次为 GPU 复制的有效像素字节、提交申请的 staging 字节、本次用到的 staging 缓冲区容量。第三项包括 32 MiB 分块的剩余空间，不能当成显存峰值。

| 场景 | 原版 | #2358 开启 | #3136 | 本地方案 |
|---|---:|---:|---:|---:|
| 单张 4096² 初传 | 64 / 64 / 64 | 64 / 64 / 64 | 64 / 64 / 64 | 64 / 64 / 64 |
| 单张 4096² 稀疏更新 | 64 / 64 / 64 | 2 / 2 / 32 | 64 / 64 / 64 | 2 / 2 / 32 |
| 8 张初传 | 170 / 170 / 256 | 170 / 170 / 256 | 170 / 170 / 256 | 170 / 170 / 256 |
| 8 张各写 1 KiB | 32 / 170 / 256 | 32 / 170 / 256 | 32 / 32 / 32 | 1 / 1 / 32 |
| 64 张初传 | 1360 / 1360 / 2048 | 1360 / 1360 / 2048 | 1360 / 1360 / 2048 | 1360 / 1360 / 2048 |
| 64 张各写 1 KiB | 256 / 1360 / 2048 | 256 / 1360 / 2048 | 256 / 256 / 256 | 8 / 8 / 32 |
| 64 张各写 64 KiB | 256 / 1360 / 2048 | 256 / 1360 / 2048 | 256 / 256 / 256 | 32 / 32 / 32 |

单 mip 场景在第 1024 和 1151 行各改 32 个 RGBA8 像素，共写 256 字节，脏页包围四行平铺块。这个构造复现 #2358 所述的 64 MiB 到 2 MiB 复制量。八张和六十四张使用规模梯度原有的 2048² 四 mip 布局；每张改 mip 1 的 32 × 8 像素。六十四张随后再各写同一 mip 的 128 × 128 像素，用于分别检验整批 64 KiB 和每张 64 KiB 两种负载。计时覆盖 Host::execute 至 fence 完成，CPU 写入和读回校验在计时区间外。

四臂分别运行了非 2 的幂尺寸、两个数组切片、三个 mip 的 RGBA8、BC1 和 BC3 测试，同批两张命令列表更新同一纹理，再更新末行和内部像素。所有子资源均与完整 detile 参考按行一致。#2358 另通过其自带的 RGBA8/BC3 稀疏带读回测试。

### 配对设计

四臂均从 6b1e408 出发。原版、本地方案、启用 #2358 和 #3136 使用同一份像素输入、提交方式和读回标准。#2358 的开关在它自己的测试提交线程上打开，生产代码保留上游默认值。原有规模梯度清单与这组专项测试共用同一个纹理函数。专项清单在同一进程中依次测单张、八张和六十四张，所有臂均按该顺序运行。

初筛以本地方案为共同参照，与原版、#2358 和 #3136 各做 15 对，从而可以直接对照两项社区实现。单 mip、八张多 mip 和六十四张多 mip 的稀疏更新时间是三个主要场景，等权比较。每张写 64 KiB 以及三档的完整初传单列为补充场景。正式窗口按对交替 A/B 与 B/A，每一对均使用同一窗口、同一驱动的两个新进程。每格复制量以实际命令记录，每一轮均核对有效像素。候选的保留还要检查默认 19 项及两个内存峰值。
