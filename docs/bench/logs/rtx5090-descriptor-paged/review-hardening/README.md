# 描述符页解除映射后的同步

对照版本为审核前的 `d369bbc`，修订版本为 `8e3d395`。两臂都包含 GPU 标记更新 `177ee68`。本次修订涉及描述符扫描和常量槽的步长写入，队列、fence、allocator 与顶层 `host.rs` 沿用审核前实现。

## 读取记录与发布步长

旧版在每个 64 KiB 写跟踪页的起始地址探测 4 字节。Windows 可以单独撤掉其中任意 4 KiB 页，也允许游戏在 GPU 资源准备期间撤掉先前可读的页。

修订版用 Windows 的 `ReadProcessMemory` 将一段连续记录复制到本地缓冲区。遇到部分不可读的范围，按 4 KiB 页分别重读；跨页记录的两段都读全才参与同步。常量槽在准备资源、重新取得槽锁后用同样方式再次读取，逐槽路径的每次重读也经内核检查。每次最多处理 256 个改动。遇到普通视图或准备期间被改写的槽，先处理该虚拟页，再给后续页分配物理位置。

常量槽先取得物理目标，再写一次步长。分配成功使用视图步长，物理页已用尽时写零。相邻槽的映射元数据仍合批写入。

## Windows 验证

默认全目标测试 266 项通过，1 项按项目设置忽略；诊断全目标测试 282 项通过，13 项忽略。新增测试经过实际的 `sync_dirty` 和 Windows 内存保护，在五个相邻的 4 KiB 页上执行两轮普通槽记录写入。第二轮先撤掉第 2 页，再在资源准备期间撤掉第 4 页，同时改写第 1 页起始槽。测试检查五个页的首尾槽：可读页采用对应的新记录，两个空洞保留此前的镜像，第 1 页的起始槽采用最后一次写入。

3 个独立热点冒烟进程均通过输出校验。像素回读得到 (1, 0.5, −0.25, 2) 和 (0, 0, 0, 0)，四个深度值为 (0.25, 0.5, 0.25, 0.25)。D3D12 Debug Layer 和 GPU-Based Validation 因本机缺少 Windows 图形工具待补。[全测与冒烟摘要](validation.txt) · [像素回读](pixel.json)

## 放弃的方案

最初的加固版本 c774bfc 每次最多复制一个 4 KiB 页。三次非正式冒烟中小负载出现额外开销，随后合并连续的安全读取，仅遇到不可读范围时逐页拆开。正式对照测量使用最终的 8e3d395。

另查过在 HLE 解除映射时递增计数的做法。XMem 自己会释放内存、撤销视图；宿主策略还允许客体通过 Kernel32、KernelBase、NTDLL 及核心 API 集取得系统导出。HLE 的单个计数无法覆盖所有使页失去可读性的路径。即使所有入口都能计数，另一线程仍能在扫描线程核对计数之后、读取记录之前撤页；读取旧快照也会漏掉准备期间的普通字节改写。没有实现该候选，未安排第二轮采样。相关入口见 [XMem](../../../../../crates/victory-hle/src/modules/xmem.rs) 与[宿主导出解析](../../../../../crates/victory-hle/src/host.rs)。
