## 测量与选择

在同一台机器上用七套 Windows 原生诊断构建的二进制。每对各起一个基线进程和一个候选进程，相邻对交换运行顺序。由正式工具预热并检查显卡状态，核心至少 2500 MHz、显存至少 13000 MHz、PCIe Gen5 ×16，P0 或 P1。实际的逐次状态、重试、输出校验及二进制 SHA-256 都在各窗口内。旧版工具测得的 10.83 ms 和 1.06 ms 使用不同显卡状态。

初筛每个候选 15 对，以 1,300 和 14,400 槽的配对耗时比的几何平均值排序，各占一半权重。前两名各加测 15 对。本地方案另将两臂交换复核 30 对。按实际二进制身份逐对计算“候选耗时 ÷ 基线耗时 − 1”，报告其样本中位数。以配对为单位重采样 5,000 次，种子 5090。表中为逐项 95% 区间，机器可读结果另列工具对 19 项耗时作 Bonferroni 校正的区间。p95 和 p99 取单臂排序后的最近秩，耗时单位为 ms。显存峰值每 10 ms 采样一次。合成回读能检查绑定和结果，未验证商业游戏帧时间。

初筛、确认、反向复核与录制争用四档合计 420 个有效进程。每个进程启动前均为 P0，核心 2535–2910 MHz、显存 14001 MHz、PCIe Gen5 ×16。4 线程争用的一次预热未达门槛，工具留存并重试。8 和 16 线程争用共有 23 次在进程退出后的采样发现核心已低于 2500 MHz，最低 1717 MHz；热点主套件的启动前、退出后采样均达门槛。

## 描述符正确性

同步逐个检查操作系统页的可读性，合并相邻可读区间，并按虚拟描述符页的 256 个槽切批。第一遍在锁内核对标签、视图 ID 和 generation。常量缓冲区的视图表项永久有效，可以先在槽锁外准备缓冲区，随后回到锁内重新读取完整记录。准备期间记录变化的槽走逐槽路径；仍有效的常量槽先连续更新映射的步长、写标记和地址信息，再建立原生描述符并登记资源引用。其他视图继续使用逐槽路径。分配不到物理页时把步长清零，恢复驻留后重新制作。

同步取得堆注册表快照后释放全局注册表锁。单个堆的生命周期保护保证销毁先摘除注册，再等待当前访问结束，最后才释放客体内存。另一个原型在同步期间一直持有注册表读锁，实测有创建堆的写者排队时会堵住后续录制，已撤回。

回归测试覆盖普通字节复制、录制线程在同步准备期间换槽、释放旧资源后 generation 失效、错误标签读零、物理页耗尽后重建，以及堆销毁和旧快照并发。在 GPU 上，同一已关闭列表连续执行四次，旧描述符表和当前 bindless 槽分别读到对应资源；构造的指纹碰撞覆盖“同指纹、不同资源”。#2821 的专门用例还检查了物理槽被清为空描述符后，同一常量必须重新建立。

## 提交顺序与并发录制

生产版 queue.rs、hold.rs、fence.rs 和顶层 host.rs 均无改动。为定位并发平台期，两份独立的诊断二进制加入相同的计时点。其中顶层 host.rs 只在 Host::execute 的宿主锁与原生 fence 等待、HostList::reset 的重置路径采样；queue.rs 记录外层队列锁、执行和列表回收。基线诊断版为 1186d69，带描述符改动的诊断版为 3707a30。

即便列表没有写入游戏可见内存，GPU 仍可能读取分配器、描述符物理页、旧缓冲区或后备缓冲区。现有同步队列在 Host::execute 返回后立即允许回收，并按队列次序处理客体 fence。当前页回收又以提交完成为前提。若要采用 #3120，需要按每次实际提交保活对象，等原生 fence 完成后再回收，并支持跨队列内存等待、客体 fence 值回退、重复执行同一列表、present 和 resize。现有 32 次提交负载在计时结束后立即回读数据。将来评估异步化应将等待最后一次 fence 纳入计时，并验证所有 32 份数据和在途页的寿命。

额外尝试了 Signal 后读取已完成值，已经完成时可以安全跳过事件等待。8 个进程的 256 次计时内提交全部未命中，已撤回。现有 Windows 测试验证了跨队列等待、fence 回退、列表重复执行和 present/resize。合成器测试先回读 32×32 的红色主平面，切换到 64×64 后回读合成像素 (127, 0, 128, 255)。
