# RTX 5090 shader 缓存与 PSO 预建的配对测量

## 缓存审核修订

在 `opt/shader-cache` 的 `b073804` 上追加了 `671e508` 和 `4583945`。Windows 回归测试用合成 shader、真实 D3D12 设备和临时缓存目录。正式 A/B 以 `b073804` 为 A、`4583945` 为 B。

- early list 存在缓存根目录。首次配置时会合并旧翻译器、驱动和构建目录下的列表，成功发布后再移除旧副本。跨进程测试依次使用已知驱动、未知驱动和另一驱动，验证三个进程都能找到之前的标题键。
- 每个缓存根保留当前翻译器及按目录修改时间最近的一代。每种适配器分别保留当前驱动及最近的一代。旧布局通过两层十六进制目录、完整适配器命名和构建目录里的普通 `host-pipelines.bin` 识别。清理逐个处理已知文件，跳过重解析点、被占用目录及陌生内容。活跃进程用 Windows 目录句柄保护正在用的代。测试覆盖核显、WARP、未标记目录、拒绝删除的文件句柄，以及全程命中仍会触发的清理。
- 初次遇到根目录旧 PSO 库时，目标为空就尝试硬链接进当前命名空间，由 D3D12 在打开时验证。目标已有库、驱动身份未知或不支持硬链接时，移除旧 blob。文件被占用时留待后续启动。驱动集成测试覆盖迁移后命中、拒绝损坏库、重建后再次命中。
- 新的预建索引跟在同一份驱动数据之后，临时文件一次替换即可发布两者。驱动只接收文件中的驱动数据部分。读回的索引留在开库时取得的字节里，按需在存库状态锁外计算标签，新的标签也在完成序列化并释放锁后计算。持有旧侧车文件的独占句柄时，新库仍能连同键集一起发布并读回。
- shader 缓存打开已有目录时清理满一小时的临时文件。回归测试用实际暂存文件验证旧文件被清掉，新文件和相似名字的其他文件保留。

## 驱动首次编译与重放

VIctory #2787 的 4,000 个预建键都与原流程一致。该步骤的 15 对配对中位耗时下降 90.20%，家族区间 [−90.32%, −89.91%]。场景也执行寄存器包匹配，单用 #2787 时这项的配对变化为 −0.31%，家族区间 [−0.91%, +1.00%]。[预建键初筛](2787-screen15/paired.json)

在同一条缺少状态名称的合成记录上，基线恢复 0/2 项，#3047 恢复光栅状态后为 1/2，叠加 #3048 后为 2/2。每组 15 对均核对恢复描述的 CityHash64。记录匹配耗时的配对变化分别为 +0.99%（家族区间 [−1.38%, +1.54%]）和 −0.47%（[−1.97%, +1.49%]）。这两项提供预建覆盖，现有样本未检出匹配耗时变化。上游报告的游戏覆盖比例未在这里复测。[光栅恢复](3047-screen15/paired.json) · [深度恢复](3048-screen15/paired.json) · [候选的逐项实测值](candidate-table.md)

#2614 独立元数据文件让新进程的 20 个 shader 热读至可用下降 4.64%，家族区间 [−7.45%, −3.10%]。原生正确性用例同时复现两个问题：固定容器散列后，更换资源解析逻辑仍返回旧值；改动持久化资源槽的一字节后，缓存接受了被改动的值。综合方案将元数据纳入翻译器及选项的同一条带校验记录。[#2614 原始 15 对](2614-screen15/paired.json) · [正确性复现](sidecar-identity.txt) · [完整候选取舍表](decisions.md)

## 复核某个对照

每个目录的 `paired.json` 记录 A、B 的确切提交和配对顺序，两个 `results.json` 记录可执行文件的 SHA-256、有效样本和正确性断言。标准及规模场景使用开发分支自带的基准。定向场景的清单在相邻的 [shader 与 PSO 场景目录](../shader-cache-community/README.md)；对应的测试源码保存在本任务独立副本的 Git 引用 `refs/benchmarks/shader-cache/forms/` 下，两臂均以相同基线添加测量代码。可以在独立目录检出任一原始记录的 A、B 提交，各自原生构建，再用同一清单重跑交替 A/B。工作集以 Windows 进程计数器为准，本地显存为 10 ms 轮询观察到的峰值。
