标准场景和大档各完成 30 对。20 个和 2,000 个 shader 的每个有效样本均通过固定的 BLAKE3 校验。大档 B 侧有一次预热未达门槛，工具记录该次尝试并重试，最终保留 30 个有效样本。标准场景的 19 项耗时与两项内存的中位数、p95、p99 及配对区间均已记录。工作集的配对中位变化为 +0.03%，逐项区间 [+0.01%, +0.10%]，校正区间 [−0.02%, +3.17%]，配对差值中位数为 +0.3125 MiB。本地显存的配对差值中位数为零。[标准 19 项与内存表](default/paired-table.md) · [同窗口原始记录](default/paired.json) · [旧版 compare-hot 对照输出](default/compare-hot.txt) · [大档全部指标](large/paired-table.md)

基线与综合平铺在独立进程中重新打开 2,000 条缓存，也验证了跨进程的收益。每个样本先由一个进程写入，再依次由三个新进程检查开头 20 条、中间 20 条、全部 2,000 条。相对于基线，综合平铺的配对中位耗时分别减少 12.98%（冷写）、24.84%（开头）、20.81%（中间）、36.35%（全量）。四个时间指标的家族 95% 区间均完全小于零。冷写工作集变化 +0.02% [−2.76%, +3.01%]，中间小批次工作集 −0.06% [−0.17%, +0.33%]。四个阶段的工作集和提交量均未出现家族区间完全大于零的结果。[15 对独立进程的逐项原始数据](large-reopen-screen15/paired.json)

## 初筛

分层数据库在同一应用的前 32 个新条目上使用普通文件，后续写入 SQLite WAL。新进程的同一冷写用例中，2,000 个条目的中位数从 1,168.641 ms 降到 521.121 ms，配对下降 55.53%。从盘上打开该库并读取第 1001 至 1020 个条目，中位数从 1.422 ms 增至 6.385 ms，配对增加 347.12%，家族区间 [+315.23%, +375.40%]。冷写工作集峰值增加 4.66%，家族区间 [+2.70%, +5.34%]。该方案因稀疏读取和内存回归淘汰，未合入选择交付的源码。这个定向场景只运行 shader 工作负载；前表大档还包含其他 GPU 工作，两个场景的绝对耗时各自比较。[四个新进程的 15 对原始数据](tiered-reopen-screen15/paired.json)

VIctory #2787 的 4,000 个预建键都与原流程一致。该步骤的 15 对配对中位耗时下降 90.20%，家族区间 [−90.32%, −89.91%]。场景也执行寄存器包匹配，单用 #2787 时这项的配对变化为 −0.31%，家族区间 [−0.91%, +1.00%]。[预建键初筛](2787-screen15/paired.json)

在同一条缺少状态名称的合成记录上，基线恢复 0/2 项，#3047 恢复光栅状态后为 1/2，叠加 #3048 后为 2/2。每组 15 对均核对恢复描述的 CityHash64。记录匹配耗时的配对变化分别为 +0.99%（家族区间 [−1.38%, +1.54%]）和 −0.47%（[−1.97%, +1.49%]）。这两项提供预建覆盖，现有样本未检出匹配耗时变化。上游报告的游戏覆盖比例未在这里复测。[光栅恢复](3047-screen15/paired.json) · [深度恢复](3048-screen15/paired.json) · [候选的逐项实测值](candidate-table.md)

## 复核某个对照

每个目录的 `paired.json` 记录 A、B 的确切提交和配对顺序，两个 `results.json` 记录可执行文件的 SHA-256、有效样本和正确性断言。标准及规模场景使用开发分支自带的基准。定向场景的清单在相邻的 [shader 与 PSO 场景目录](../shader-cache-community/README.md)；对应的测试源码保存在本任务独立副本的 Git 引用 `refs/benchmarks/shader-cache/forms/` 下，两臂均以相同基线添加测量代码。可以在独立目录检出任一原始记录的 A、B 提交，各自原生构建，再用同一清单重跑交替 A/B。工作集以 Windows 进程计数器为准，本地显存为 10 ms 轮询观察到的峰值。
