# 分开测量首次见到的 DXIL 和跨进程重放

在 WaveOps 基线 177ee68 上，原有大档串行创建 1,996 个 PSO 的一次普通测试用时 40.811 秒。同一普通构建时段，集成候选用时 37.730 秒。此前 6b1e408 正式大档的基线中位数是 0.866 秒。两批样本的 DXIL 和测试窗口不同，这些数字不足以判断 NVIDIA 驱动缓存的影响，也不能用于计算优化收益。[WaveOps 字节摘要与原始时长](wave-digests.txt) · [旧基线大档的 30 对样本](large/paired.json)

新增场景沿用大档的 1,996 个模糊着色器、宽度与资源布局。每轮为缓冲区写入位置的整数计算加入同一个随机 32 位常量。对任意输入字 x 和常量 s，模 2³² 运算下，x+s−2(x&s) 等于 x^s。再与 s 异或就得到原值。浮点模糊、纹理写入、缓冲区位置和像素值保持一致。原有固定输入和实际产品翻译流程继续使用原有指令。

每轮运行两个独立的 Windows 测试进程。每个进程使用自己的空内存 PSO 库，默认关闭 VIctory 每 20 秒一次的磁盘序列化。设置 VICTORY_BENCH_DRIVER_APP_DISK=1 可以使用每进程独立的临时目录复现原大档的周期性保存。每个进程在计时前翻译整批输入，核对所有 DXIL 互不相同，再经正常的 Prebuild::make 路径创建 PSO。两次都要求实际创建 1,996 个，应用库命中为零。第二进程复用第一进程的常量，并逐项核对批次摘要、总字节数和最大条目大小。同一组 GFX10 指令还对四个不同的 32 位像素分量执行，在 RTX 5090 上回读比较两个 texel。样本打印可复现的常量和 DXIL 集合摘要。两进程均校验设备为同一款硬件适配器。

测试分别记录第一项可用时间、整批创建时间和进程工作集峰值。首次与重放的差能显示相同驱动输入在独立进程中是否获得收益。驱动内部是否缓存、是否落盘，需结合成对结果判断。整个过程无需操作驱动缓存目录。

原有大档在一个进程中串行调用预建，随后在本进程的应用库逐个查找。现有预建命令行会使用系统报告的可用线程数，本机为 24。默认调度的参照是 24 个工作线程。单线程用于与原有基准对照。混合体积场景在每第四个着色器的同一个整数位置叠加等价变换，比较固定并发和按实际 DXIL 字节限制在途任务；大于预算的条目可以单独运行。调度策略不参与生成着色器和 PSO 键。

可复现的测试源保存在本任务独立副本的 refs/benchmarks/shader-cache/driver-wave-base。driver-cache-large 和 driver-cache-mixed 两份场景清单位于该提交的 docs/bench/suites/scale 下。两臂可以在同一常量下复核调度前后的字节摘要；正式首次创建采样由每一臂独立选取新常量。
