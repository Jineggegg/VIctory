# 2,000 条 shader 写入的分项计时

修复基线 6b1e408 与仅改文件布局的候选分别插入同样的计时点。每个批次创建独立目录，在新的原生 Windows 进程运行，先跑一对预热，保留六对交替样本。两个程序均产出既定的 2,000 个 DXIL。为便于区分操作耗时，下表汇总每一批 2,000 次调用，单位为毫秒。

| 创建临时文件 | 247.754 / 273.369 / 273.369 | 271.097 / 381.084 / 381.084 |
| 写入内容 | 99.284 / 106.511 / 106.511 | 98.622 / 131.181 / 131.181 |

平铺方案在缓存根目录初始化时创建翻译器目录。每条记录直接在该目录创建临时文件，写完后原子重命名。基线在重命名前关闭句柄；平铺在发布后关闭。六个批次的 p95、p99 均为最大值。此表没有采集文件系统过滤驱动事件，也没有变更 Defender 设置。所有条目的实际纳秒计时见[原始记录](cache-file-io-large.txt)。
