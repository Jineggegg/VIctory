# RTX 5090 编译缓存候选，正确性基线更新前的记录

正式采样为 0/30。两次 `gpu-quiet` 在保存 PearlIdle 原状态时发现它处于故障锁定，均在暂停服务前退出。主线程随后要求等 NVIDIA 正确性修复合入并发布新基线后再正式采样。本记录供下一轮复核。

## 实现

缓存使用带预编译查询的 SQLite WAL。首次查找时打开数据库并建表，这部分耗时计入空缓存场景。每条记录的 BLAKE3 校验覆盖键和内容。并发读写与崩溃回滚交给事务处理，热读解码真实的持久化记录。翻译失败原因也参与校验并缓存。PSO 库按翻译器、适配器标识、软件适配器标志和可用的驱动版本分目录。驱动仍验证载入的 blob，拒绝后从空库创建。驱动版本不可查询时，使用独立的 unknown 目录并由驱动验证兼容性。分支还包含上游 #3152 的控制流计划复用。

## 正确性和测量

代码提交为 `337b1f0`。3 个全新的 Windows smoke 进程都通过完整热点断言，每次 20 个 shader 共 77,333 字节，集合 BLAKE3 均为 `6a3b8c756f04aa62ade1d92871430c8a1326354061bb5d52a9266ddb2936090f`。三种翻译路径逐字节比较。像素和深度回读通过，D3D12 Debug Layer 与 GPU-based validation 待补。

## 测试与后续复核

Windows 原生 GPU crate 最后一次全量测试为 232 通过、2 失败、1 忽略。新增的并发连接写同一键、写进程中途退出、缓存身份隔离均通过，读回损坏记录及驱动拒绝 blob 的回退也通过。两个失败与原基线的动态描述符槽、页表视图断言一致。

恢复原基线的完整 shader 测试路径时，直接索引纹理标记用例发生相同访问冲突。单独跑其余单元用例得到 299 通过、3 失败、3 忽略。三个失败为缓冲区步长、空视图和指定层级 gather，与基线相同。资源跟踪集成测试 3 通过、1 忽略。

逐条 fsync 在原 shader 缓存代码中并不存在。当前方案没有把写入移到后台，因此冷场景仍计入事务提交。最初在第一次读取时总是查询 DXGI 适配器，非正式调试中单个 PSO 首次可用中位数为 2.3135 ms。改为先检查该翻译器的目录，空缓存可直接跳过此次查询。正式效果待测。

已验证的 Windows 日志与 JSON 同目录保存。新基线会改变翻译选项及预期 DXIL，合并时必须保留描述符分页选项参与缓存身份，再将候选输出与同版基线逐字节复核。这里的旧摘要仅用于本次同版对照。

## 单独测量 bitcode 计划复用

在 Windows 原生 diag 构建中，两条路径处理同一个 `synthetic(regs, stages, read)` 模块。旧路径依次执行 `uses()`、`write()`，新路径调用一次 `plan()`，再向 `uses_of`、`write_with` 传入同一计划。计时前断言两份 bitcode 字节相同。两路径的结果均交给 `black_box`。每个计时值平均五次调用，每对交替翻转先后顺序，丢弃两对预热后记录 30 对。95% 区间对整对样本有放回重抽 5,000 次，种子为 5090，统计量为两列中位数之比减一。此 CPU 微基准只覆盖 bitcode 阶段。

| 合成模块（regs / stages / read） | 原路径中位 ms | 复用中位 ms | 变化 | 95% 区间 |
|---|---:|---:|---:|---:|
| 64 / 64 / 64 | 0.17426 | 0.13911 | −20.17% | [−20.46%, −18.05%] |
| 128 / 256 / 32 | 1.66228 | 1.35950 | −18.21% | [−21.99%, −15.01%] |
