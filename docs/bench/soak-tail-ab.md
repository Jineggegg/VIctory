## 合并相邻页读回的候选

C 在重新启用写入跟踪后，将连续且已成功处理的完整 64 KiB 分片合并读回，每次最多 1 MiB。合并读取失败时逐片重试，部分分片继续单独更新基线。在先 C 后 B 的对照中，C 的最高分钟 p99 从 B 的 2.031 升到 2.671 ms，p50 从 1.223 升到 1.325 ms。反序时，C 的最高分钟 p99 从 2.151 降到 2.129 ms，p50 从 1.240 降到 1.213 ms。两种顺序的效果相反，放弃该改动。44 分钟共 1,959,144 轮，逐字校验失败与设备移除均为零。538 次运行中采样均未记录外部 3D/Compute。[分钟与校验数据](logs/soak-tail-spikes/ba-minutes.txt) · [窗口一采样和指纹](logs/soak-tail-spikes/ab-windows.txt) · [窗口二采样和指纹](logs/soak-tail-spikes/ba-windows.txt)

## 测量口径

A 是原验收基线 `6b1e408` 的独立副本。B 使用 `418a384` 的 GPU 实现，和本次文档分支的基线 `e071177` 在该包内相同。每个进程独立通过十次 GPU 空闲采样（均值 ≤8%、单次 ≤10%）和三秒稳定预热。每个窗口独占共享 GPU 锁和四个构建槽，运行中每五秒采样一次外部 3D/Compute。每轮对 1 MiB 做相同的 CPU 填充、GPU XOR、围栏等待、快照回写和逐字校验。两版均使用 Windows x64 diag 和 diagnostics 特性。

A、B、候选 C 使用相同的十段墙钟计时与提交线程 CPU 周期计数。每分钟保留全部轮次，按整轮延迟的最近秩计算分位，并与基准程序原生输出逐项核对。表中 p50、p99 中位数均按分钟计算；单轮越线率的分母是该版本所有轮次。连续轮次共享系统状态，复测次数按独立进程和窗口计算。CPU 周期含用户态和内核态执行，保留原始单位。[微软对线程周期计数的说明](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-querythreadcycletime)

调度探针单独构建，只运行 B。在提交线程和最后结束的工作组上读取 Windows 原生线程切换计数与等待原因位图，并在每轮前后读取进程页错误计数。一次区间可有多个等待原因，系统没有在这份位图中给出每个原因的持续时间。线程池汇合含等待回调结束和关闭工作项，汇合与最后完成组都包含在回写内，耗时有重叠。该探针有额外开销，其绝对延迟单列。[微软对线程调度计数的说明](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-performance_data)
