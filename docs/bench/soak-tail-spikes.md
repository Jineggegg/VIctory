## 反序与工作线程数对照

第二个临时诊断版在同一预留窗口内依次跑三个三分钟进程。默认模式在本负载使用四组工作，调用线程也参与。单后台回调模式保留全部四个工作组和重映射保护，只限制提交给 Windows 线程池的回调数。每个进程都重新过十次空闲采样和相同预热判据。[窗口与指纹](logs/soak-tail-spikes/windows.txt) · [分钟记录](logs/soak-tail-spikes/minutes.txt)

| 同窗顺序 | 轮数 | 分钟 p50 中位数 | 最高分钟 p99 |
|---|---:|---:|---:|
| 先串行 | 101,349 | 1.788 ms | 3.271 ms |
| 再默认并行 | 136,309 | 1.232 ms | 2.072 ms |
| 最后只投递一个后台回调 | 128,871 | 1.334 ms | 2.021 ms |

限制后台线程使最高分钟 p99 少了 0.051 ms（2.4%），分钟 p50 中位数增加 0.101 ms（8.2%）。默认组在这个窗口的三分钟均未越过 2.695 ms，无法用它证明受限线程数抑制了尖峰。五组共 19 分钟、754,826 轮，所有分钟的校验失败和设备移除计数均为零，233 次运行中采样均未记录外部 3D/Compute。[原生输出](logs/soak-tail-spikes/native.txt) · [运行中 GPU 采样](logs/soak-tail-spikes/gpu.txt)

串行第 3 分钟的 p99 为 3.271 ms。取接近 p99 的 67 轮，平均整轮 3.273 ms，发布 1.183 ms。组内精确写入 0.764 ms、生成和检查掩码 0.214 ms、读取目标页 0.146 ms、申请临时缓冲 0.005 ms、取得写保护 0.042 ms。提交后的命令列表回收另占 0.393 ms；同一分钟接近 p50 的轮次在回收上花 0.207 ms、精确写入上花 0.383 ms。并行模式的组内数字只取每轮最后完成的组；串行模式整轮只有一个组。所有数字均为墙钟时间，包含运行线程被调度出去的时间。[组内与列表回收计时](logs/soak-tail-spikes/detail.txt) · [整轮计时](logs/soak-tail-spikes/phases.txt)

## 方法

默认并行、强制串行各起一个持续五分钟的新进程，切换仓库已有测试开关 `FORCE_SEQUENTIAL`。每轮 CPU 填充同一段 1 MiB 模拟主机内存，GPU 对 262,144 个 u32 做 XOR，主线程等待围栏、执行快照回写并逐字验证。这里的 `gpu_writes(..., false)` 声明走快照回写，无法测出标记页回写的尾延迟。[原生混合负载](../../crates/victory-gpu/src/pipeline/hot/soak.rs) · [快照与写入保护](../../crates/victory-gpu/src/shadow.rs)

使用单调时钟，每分钟独立计算全部轮次的分位数，在计时结束后保留最慢的 2%、按延迟排名每 100 轮取一轮，以及进程首轮。工作项创建、投递、调用线程执行及回调汇合分别计时；后台首回调延迟与调用线程工作可重叠。每组持有共享 GPU 锁并预留全部四个构建槽，用原验收的十次采样门槛（均值 ≤8%、单次 ≤10%）和至少三秒预热判据，运行中每五秒采样 GPU 引擎。两组均为 Windows x64 的 diag 构建。[窗口记录](logs/soak-tail-spikes/windows.txt)

临时探针只用于诊断。线程运行时间与可运行后等待系统调度的时间尚未区分，旧 A 也没有逐轮阶段数据。若继续定位 A/B 的差异，优先在同一窗口给 A、B 采集相同的逐轮阶段和调度轨迹。

## 正确性验证

工作分支在采样后快进至 `e071177`，相对采样基线只有 XAsync 文件变化。移除临时计时后，两套 Clippy 均通过。Windows 工作区测试为 29 个顶层程序，977 通过、13 忽略；GPU 包连跑三轮，每轮 2 个顶层程序、321 通过、4 忽略。子进程自行打印的测试汇总未重复计数。 Debug Layer 与 GPU-based validation 均已启用，错误数为零。仓库策略检查通过。本次改动仅为调查说明和日志，没有待验收的生产修复，默认 19 项性能基准沿用原验收结果。[验证结果与各程序计数](logs/soak-tail-spikes/validation.txt)
