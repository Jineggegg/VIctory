# RTX 5090 正确性修复后的热点基线

后续优化以 `dac46f7` 的 30 次正式采样为基线。每次都启动一个新的 Windows x64 进程，全部通过应用层断言和 GPU 回读。相较旧基线 `71371a3`，19 个耗时指标中有 18 个中位数上升且 95% 区间排除零。同步 14,400 个脏描述符的中位数下降 0.19%，区间跨零。本次没有检出超出噪声的提速。[正式结果](logs/hot-rtx5090-fixed/results.json) · [旧基线](logs/hot-rtx5090/results.json) · [逐指标对比](logs/hot-rtx5090-fixed/compare.txt)

- **最大相对变化出现在两个 GPU dispatch。** 同页写标记从 0.9894 ms 升至 6.0973 ms（+516.24%），循环内地址解析从 0.4768 ms 升至 5.6793 ms（+1,091.24%）。两批都验证了 262,144 个 lane，循环场景均完成 2,097,152 次全局加载。GPU timestamp 包围整次 dispatch，包含最终写回等指令。
- **按本基准的单次负载，耗时最高的三项**是标记页回写（118.3162 ms）、256 MiB host 刷新（63.4399 ms）和多 mip 纹理初传（59.7980 ms）。20 个 shader 写入空缓存的 p99 达 114.6475 ms，中位数为 26.7027 ms。32 次提交也有长尾，p99 为 32.9775 ms。
- **DXIL 集合发生变化。** 两批输入均为 20 个相同的合成 shader。旧集合为 77,333 字节，BLAKE3 为 `6a3b8c756f04aa62ade1d92871430c8a1326354061bb5d52a9266ddb2936090f`。新集合为 88,177 字节（+14.02%），BLAKE3 为 `a0c629eda000e64f6a98240935c1cda672a72df20184c884832d2da2831b69f8`。各自 30 次内哈希一致，每次还验证了无磁盘缓存、缓存冷和缓存热三条路径的 DXIL 逐字节相同。

## 测量范围与环境

描述符负载仍在 32,768 个逻辑槽中分散改写 1,300 或 14,400 个槽，计时始末仍是调用并返回 `descriptor::sync_heaps`，包括分页同步的实际成本。提交 `451227b`（在最终历史中为 `93fa254`）更改了计时后的校验着色器。GPU 从真实物理堆起点按 GPU 页表定位每个改写槽并读取常量。全堆记录 ID、代数和所有改写槽的常量均继续核对。19 个计时区间和操作规模保持一致。两个进程级内存峰值覆盖了新的回读资源和分页资源。提交的三个子项时间均包含于总时间中，队列提交至 fence 返回也包含 fence 等待。[热点场景与原测量边界](hot-rtx5090-2026-11-26.md) · [逐轮回读及指标](logs/hot-rtx5090-fixed/run.txt)

两批均使用 RTX 5090、驱动 621.14、Ultra 9 285K、Windows 10.0.26300（Windows 11）及 rustc 1.98.1，采用 diag 优化配置。新样本启动前 GPU 利用率为 1–2%，温度 40.7–42.7 °C。旧样本分别为 0% 和 43.9–47.2 °C。两批由不同时间窗口采得，区间描述批内样本波动，不能将每个差值归因到某一项修复。新窗口预留全部四个构建槽，验证连续空闲 12.5 秒，结束后 Comfy 和 Swarm 均恢复 active，PearlIdle 保持采样前的暂停状态。[GPU 窗口与恢复日志](logs/hot-rtx5090-fixed/window.txt)

## 全部指标

每批 30 个独立进程。p95/p99 采用最近秩，30 次的 p99 为最大值。标准差为样本标准差。变化按未舍入的中位数计算，95% 区间为两批独立重采样 5,000 次得到的百分位区间，未作多重比较校正。工作量指标使用原计数。显存为 10 ms 轮询得到的本地显存峰值下界（十进制 MB），工作集为 Windows 记录的进程峰值（MiB）。
